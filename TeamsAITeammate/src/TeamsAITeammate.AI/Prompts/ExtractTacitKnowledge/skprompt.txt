## 指示

トランスクリプトから暗黙知の候補を抽出してください。
以下のパターンに注目してください:

### 検出パターン
- **DecisionBackground**: 「理由は〜」「背景として」「元々は〜だった」→ 意思決定の背景・理由
- **UndocumentedProcess**: 「いつもこうしている」「慣例として」「うちのやり方では」→ 未文書化の業務プロセス
- **ExpertKnowledge**: 「私の経験では」「前のプロジェクトでは」→ 個人の専門知識・ノウハウ
- **DiscussionHistory**: 「前回の会議で」「以前議論した時に」→ 議論の経緯・コンテキスト
- **OrganizationalContext**: 「部門の方針として」「上層部の意向は」→ 組織的な背景情報
- **TechnicalInsight**: 具体的な技術的判断の根拠、設計思想 → 技術的な知見
- **LessonsLearned**: 「前に失敗した時は」「反省点として」→ 教訓・過去の失敗から学んだこと
- **StakeholderRelationship**: 「〜さんに確認が必要」「〜チームとの調整」→ ステークホルダー関係性
- **ImplicitAssumption**: 明示されていない前提条件、暗黙の了解 → 暗黙の前提条件
- **DomainExpertise**: 具体的な数値・期限の根拠、業界特有の知識 → ドメイン固有の専門知識

JSON配列で出力してください:
```json
[
  {
    "category": "TacitKnowledgeCategory",
    "content": "抽出された暗黙知の内容",
    "context": "どの会話文脈から抽出されたか（該当箇所の引用）",
    "sourceSpeaker": "発言者名",
    "confidence": 0.0-1.0,
    "relatedTopics": ["関連トピック"],
    "requiresValidation": true/false
  }
]
```

抽出のルール:
1. 明確に文書化されていないと推測される知識のみ抽出する
2. 一般的な意見や感想は除外し、組織固有の知識に焦点を当てる
3. confidenceは抽出の確信度（0.5未満は含めない）
4. requiresValidationは内容の正確性に人間の確認が必要な場合にtrue
5. JSON以外のテキストは出力しないでください
